# Security Policy

FAB processes financial documents, accounting records, and provider credentials. Do not report a vulnerability in a public issue, discussion, pull request, or email containing exploit details or personal/financial data.

## Report Privately

Use GitHub's **Report a vulnerability** action on this repository's Security page. Private vulnerability reporting is enabled. This keeps the report visible to repository maintainers. Include the affected commit/release, impact, prerequisites, and a minimal reproduction using synthetic data. Never attach receipts, bank statements, account numbers, OAuth tokens, passwords, encryption keys, or customer data.

If private reporting is unavailable, contact the repository owner through the contact method on the owner's GitHub profile and request a secure channel before sending technical details. Do not assume a public issue or profile email is private.

## Response and Disclosure

This project is maintained on a best-effort basis. No guaranteed response or remediation time is offered. The maintainer will acknowledge and assess valid reports when available, coordinate remediation and disclosure where practical, and may request clarification through the private report. Please allow a reasonable opportunity to investigate and fix an issue before public disclosure.

## Supported Versions

The initial FAB release is a development preview. The latest main branch and newest published release are the review targets; no service-level response commitment is offered. Users should update to the newest release and rotate any credential that may have been exposed.

## Scope and Limitations

This policy does not claim that FAB is penetration-tested, certified, or compliant with financial, tax, or privacy regulations. Never send live provider credentials or production financial data as part of a report.
