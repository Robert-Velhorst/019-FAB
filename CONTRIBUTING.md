# Contributing

Thanks for considering a contribution.

## Before you start
- Read the repository README and any project instructions near the code you plan to change.
- Keep changes focused and preserve existing behavior and user data.
- Do not commit credentials, access tokens, private user data, production backups, or other secrets. Use synthetic examples.
- For security vulnerabilities, use GitHub's private vulnerability reporting when available. Do not post exploit details publicly.

## Changes and checks
- Explain the problem and the proposed change.
- Run relevant checks for the area you changed. In your pull request, list the exact commands and results; if you could not run a check, say so.
- Update documentation when behavior or setup changes.
- Call out compatibility, data migration, deployment, and rollback implications when relevant.

## Pull requests
Use the pull request template. Link related issues when useful and keep discussion respectful and focused.
